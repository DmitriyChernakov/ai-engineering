# Зачем?
- Задает роль и рамки для модели
- Превращает универсальную LLM в узкого специалиста
- Задает тон, стиль общения и ограничения
 
## Базовые правила хорошего system prompt:
 
- при указании роли быть более конкретным  (Кто ты? Что и как делаешь?)
- заставлять рассуждать агента, прежде чем отвечать
- указывать формат ответа
- заменять запреты на инструкции

============================================================
Роль: Прагматичный ментор
============================================================
Да, стоит.

1. **Узконаправленность Python**: Хотя Python широко распространен, специализированные языки могут быть особенно ценны в определенных областях. Rust может быть полезен для тестирования системного уровня, особенно если тестирование критических систем является частью вашей работы.

2. **Преимущества Rust**: Rust известен своей безопасностью и эффективностью. Изучение Rust может повысить вашу способность тестировать производственные системы, особенно если они используют системы на C или C++.

3. **Рост спроса**: По данным различных исследований, Rust становится все более популярным среди разработчиков. Изучение этого языка может улучшить ваши перспективы на рынке труда, особенно если вы переходите к более ответственным и критическим проектам.

============================================================
Роль: Восторженный евангелист
============================================================
ОБЯЗАТЕЛЬНО! 🚀 Python — это отличный язык, но Rust открывает целый новый мир возможностей. В 2026 году Rust станет еще более важным в IT-индустрии. 

Вот несколько причин, почему стоит учить Rust:

1. **Скорость и эффективность** 🚀: Rust позволяет создавать быстрые и эффективные приложения без ущерба для безопасности. Это особенно важно для серверного программирования и системного программирования.

2. **Производительность критических систем** 🛠️: Rust обеспечивает надежность и безопасность, что особенно важно для систем, где ошибки могут быть критическими.

3. **Фреймворки и инструменты** 🌐: ManyDev и другие компании используют Rust для создания инструментов и фреймворков, которые становятся все более популярными.

4. **Проекты в области IoT и встраиваемой техники** 💻: Rust отлично подходит для разработки программного обеспечения дляIoT-устройств и встраиваемых систем, где требуется высокая надежность.

5. **Карьера** 🎉: Навыки Rust будут цениться на рынке труда. Многие компании ищут специалистов с навыками Rust для разработки критически важных систем.

Примеры успешных проектов на Rust:
- **Cargo** — управляющая программа для сборки Rust проектов.
- **Tauri** — фреймворк для создания интерфейсов пользовательского интерфейса.
- **Tokio** — библиотека для асинхронной работы с сетевыми приложениями.

Учитывая ваши нынешние навыки и область работы, вы сможете быстро освоить Rust и применить его в своей текущей роли в QA. Это будет отличным дополнением к вашим навыкам Python, и вы сможете работать над более сложными и интересными проектами! 🙌

============================================================
Роль: Скептик-реалист
============================================================
Конечно, стоит, но с оговорками. Rust — это мощный инструмент для системного программирования, и его знание может пригодиться даже в QA. С течением времени QA-инженеры все больше пересекаются с инфраструктурой и серверной логикой, поэтому Rust может добавить вам ценности.

Однако учите его осознанно. Rust сложнее чем Python и требует времени на освоение. Плюс, его использование все еще не так широко распространено в QA-средах, как Python, так что вы можете столкнуться с некоторыми ограничениями в выборе проектов.

Если вы все же решите учиться Rust, начните с основ и постепенно переходите к сложным концепциям. И помните, что не все задачи QA требуют использования Rust — часто Python более чем достаточно.

### Анализ Требования
Фича: Форма логина  
Поля:  
- Поле email  
- Поле пароль  
Кнопка:  
- 'Войти'  
Ссылка:  
- 'Забыли пароль?'

### План Тест-Кейсов

#### Тест-Кейс 1: Проверка входа с корректными данными
**Цель**: Проверить успешный вход в систему с помощью корректных данных.

**Шаги**:
1. Открыть страницу входа.
2. Ввести корректный email.
3. Ввести корректный пароль.
4. Нажать кнопку 'Войти'.

**Ожидаемый результат**: Пользователь успешно проходит аутентификацию и перенаправляется на главную страницу или страницу с необходимым контентом.

**Негативные сценарии**:  
- Проверка на наличие ошибок или сообщений об ошибке.
- Проверка на корректное перенаправление пользователя.

---

#### Тест-Кейс 2: Проверка входа с некорректным email
**Цель**: Проверить поведение при вводе некорректного email.

**Шаги**:
1. Открыть страницу входа.
2. Ввести некорректный email (например, "test").
3. Ввести корректный пароль.
4. Нажать кнопку 'Войти'.

**Ожидаемый результат**: Система должна выдать сообщение об ошибке или предупреждение о некорректности email.

**Негативные сценарии**:  
- Проверка на отсутствие перехода на следующую страницу без корректного email.

---

#### Тест-Кейс 3: Проверка входа с некорректным паролем
**Цель**: Проверить поведение при вводе некорректного пароля.

**Шаги**:
1. Открыть страницу входа.
2. Ввести корректный email.
3. Ввести некорректный пароль.
4. Нажать кнопку 'Войти'.

**Ожидаемый результат**: Система должна выдать сообщение об ошибке или предупреждение о некорректности пароля.

**Негативные сценарии**:  
- Проверка на отсутствие перехода на следующую страницу без корректного пароля.
- Проверка на наличие сообщений о попытках входа с неправильным паролем.

---

#### Тест-Кейс 4: Проверка входа без заполнения полей
**Цель**: Проверить поведение при попытке входа без заполнения полей.

**Шаги**:
1. Открыть страницу входа.
2. Нажать кнопку 'Войти' без заполнения полей.

**Ожидаемый результат**: Система должна выдать сообщения об обязательности заполнения полей.

**Негативные сценарии**:  
- Проверка на отсутствие перехода на следующую страницу без заполнения обязательных полей.
- Проверка на наличие сообщений об обязательности заполнения полей.

---

#### Тест-Кейс 5: Проверка перехода по ссылке 'Забыли пароль?'
**Цель**: Проверить переход на страницу восстановления пароля.

**Шаги**:
1. Открыть страницу входа.
2. Нажать на ссылку 'Забыли пароль?'.

**Ожидаемый результат**: Пользователь должен быть перенаправлен на страницу восстановления пароля.

**Негативные сценарии**:  
- Проверка на отсутствие перенаправления на некорректные страницы.
- Проверка на наличие логических ошибок при нажатии на ссылку.

---

### Заключение
Эти тест-кейсы покрывают основные функции и граничные случаи для формы входа. В зависимости от спецификации системы, может потребоваться дополнительное тестирование, например, проверка на наличие CSRF-токена, проверка на защиту от атак или другие особенности системы.
