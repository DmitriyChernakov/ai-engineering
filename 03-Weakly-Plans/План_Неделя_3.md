## День 17 (Ср). Архитектура RAG-пайплайна

**Тип задачи**: архитектурная

**Задача**: Спроектировать RAG-пайплайн для qabrain — ассистента по QA-документации.

**Что есть:**
- QA-документация: требования, описания фич, тест-планы
- Облачный embeddings API (размерность 2560)
- Облачная чат-модель
- Langfuse для observability

**Что нужно сделать:**

1. **Нарисовать схему** (Mermaid, Excalidraw или бумага) из двух этапов:
    - **Индексация** (offline, один раз): документы → чанки → векторы → хранение
    - **Запрос** (online, каждый раз): вопрос → вектор → поиск → контекст → ответ с цитированием
2. **Выбрать параметры чанкинга**:
    - Размер чанка (например, 512 токенов)
    - Overlap между чанками (например, 50 токенов)
    - Обосновать выбор
3. **Выбрать векторную БД для MVP**:
    - **В памяти (dict/list)** — самое простое, для 3 документов
    - **Chroma** — легковесная, популярная для прототипов
    - **Qdrant** — production-ready, но тяжелее
    - Обосновать выбор для qabrain
4. **Определить стратегию цитирования**:
    - Что хранить в metadata (имя файла, номер раздела?)
    - Как LLM будет ссылаться на источники в ответе


**Инструменты**: бумага + ручка или Mermaid

**Критерии успеха**:
- Схема с двумя этапами нарисована
- Параметры чанкинга выбраны и обоснованы
- Векторная БД выбрана для MVP (с обоснованием)
- Стратегия цитирования определена
- Можешь объяснить схему за 2 минуты

**Формат ответа в чате**:

